# Первая настройка

Один раз, около 10 минут. Делается с компьютера.

## 1. Репозиторий
1. GitHub → New repository, имя например `elektro-site-check`.
2. **Public** — тогда минуты GitHub Actions безлимитные. В отчётах только метрики публичного сайта, ключи в логи не попадают.
3. Ветка по умолчанию должна называться `main`.
4. Распакуйте `site-check-repo.zip` и загрузите **содержимое** (не папку-обёртку) в репозиторий: Add file → Upload files, перетащите все файлы и папки, включая `.github`. Скрытую папку `.github` проводник иногда не показывает — включите показ скрытых файлов. Если не загружается, создайте файл `.github/workflows/site-check.yml` через Add file → Create new file (в поле имени набирайте путь со слешами) и вставьте текст.

## 2. Секреты
Settings → Secrets and variables → Actions → New repository secret. Три секрета:

| Имя | Значение |
|---|---|
| `PSI_KEY` | ключ Google PageSpeed Insights API (Google Cloud → APIs → PageSpeed Insights API → Credentials). Ограничьте ключ только этим API |
| `TG_TOKEN` | токен того же Telegram-бота, что у деплоя сайта |
| `TG_CHAT_ID` | id чата, куда бот пишет |

Значения не показываются после сохранения — это нормально. В репозиторий и в чат ключи вставлять не нужно.

## 3. Права Actions
Settings → Actions → General → Workflow permissions → **Read and write permissions** → Save. Иначе бот не сможет закоммитить отчёты.

## 4. Первый запуск
1. Положите в `inbox/` архив `2026-10-30-first-standard.zip` (Add file → Upload files → Commit changes).
2. Вкладка Actions → запуск `site-check` должен появиться через несколько секунд.
3. В Telegram придёт «▶️ старт», по окончании — сводка и файл отчёта. Первый `standard` с 2 потоками идёт примерно 15–25 минут.
4. Отчёт появится и в `reports/`, а архив из `inbox/` исчезнет.

## Если что-то не так
| Симптом | Причина |
|---|---|
| Actions не запустился | ZIP лежит не в `inbox/` или не `.zip`; либо ветка называется не `main` |
| Тест прошёл, но коммита нет | не включены права записи (шаг 3) |
| В Telegram тишина | неверные `TG_TOKEN`/`TG_CHAT_ID`; текст ошибки виден в логе шага «Обработать очередь заданий» |
| PSI отвечает 429 | не задан или неверен `PSI_KEY` |
