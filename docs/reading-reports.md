# Как читать отчёт

Порядок чтения: **Итоги → Топ причин → таблица CWV → что изменилось → серверная диагностика → замечания → детали**.

## Пороги (критерии Google)
| Метрика | 🟢 хорошо | 🔴 плохо |
|---|---|---|
| LCP | ≤ 2,5 с | > 4 с |
| FCP | ≤ 1,8 с | > 3 с |
| TBT | ≤ 200 мс | > 600 мс |
| CLS | ≤ 0,1 | > 0,25 |
| TTFB | ≤ 800 мс | > 1,8 с |
| INP (только реальные пользователи) | ≤ 200 мс | > 500 мс |
Оценка PSI: 🟢 ≥ 90, 🟡 50–89, 🔴 < 50.

## Топ причин: что значит и что делать
| Формулировка | Смысл | Куда смотреть |
|---|---|---|
| TTFB высокий | медленный ответ сервера/CDN | раздел «Серверная диагностика»: `cf-cache-status`, `cache-control`, сжатие |
| этап LCP «Resource load delay» | LCP-картинка найдена браузером поздно | `fetchpriority="high"`/preload, убрать `loading="lazy"` у главной картинки |
| этап «Resource load duration» | файл LCP тяжёлый | размер и вес картинки, формат |
| этап «Element render delay» | после загрузки отрисовку задерживают CSS/JS | блокирующие ресурсы, главный поток |
| блокирующие ресурсы | CSS/JS в `<head>` без defer/async | список файлов в причинах |
| TBT: сторонний скрипт | GTM, Clarity и т.п. занимают главный поток | отложить загрузку, сузить триггеры |
| TBT: свой JS | долгие задачи в нашем скрипте | «Длинные задачи» и «JS по времени» в деталях |
| неиспользуемый JS | грузим код, который не исполняется | разделить бандл, убрать лишнее |
| DOM > 1500 | тяжёлая разметка | упростить блоки, ленивая отрисовка длинных списков |

## Сравнение с прошлым
- Для каждой пары «страница + режим» берётся последний предыдущий замер из `reports/*.json` того же адреса.
- `~` в столбце «К прошлому» — изменение в пределах шума, не повод для выводов.
- 🔻 регрессия — падение больше шума, либо LCP хуже на 0,7+ с при падении оценки.
- 📈 рост HTML — страница стала тяжелее минимум на 5 КБ и на 20%.

## Серверная диагностика
Пять запросов к каждой ключевой странице с runner'а GitHub. Что смотреть:
- **ответ мин/мед/макс** — большой разброс значит нестабильный сервер/кэш;
- **cf-cache-status** у HTML на Cloudflare Pages обычно `DYNAMIC`; у ассетов должен быть `HIT` при повторном запросе;
- **cache-control** у `/_astro/*` — желательно год (`immutable`); короткий срок = повторные визиты грузят всё заново;
- **сжатие** — у HTML, JS и CSS должно быть (`br`/`gzip`).
