# История изменений

## v2.2 — 2026-10-31
- Сообщения Telegram: принятое задание (режим, прогоны, цель), обновлённое расписание списком, старт и конец каждого теста с временем (Киев) и длительностью; для запусков по расписанию — «По расписанию «имя»: …» с плановым временем и задержкой.
- Рядом с каждым отчётом сохраняется `*.meta.json` (старт, конец, длительность, источник запуска).

## v2.1 — 2026-10-31
- Обновление через ZIP стало безопасным: архив сначала распаковывается во временную папку, проверяются JSON, синтаксис скриптов (`node --check`) и пробный запуск `process-jobs.mjs` / `site-check.mjs help`. Если проверка не пройдена — репозиторий не меняется, в Telegram приходит причина.
- Запуск по расписанию: файл `targets/schedule.json`, проверка каждые 30 минут (нужен `schedule` в workflow, см. `docs/schedule-and-updates.md`). Расписание — необязательная опция: нет файла — ничего не запускается.
- Telegram: сообщение «скрипты обновлены» и «пропущено по расписанию».
## v2.0 — 2026-10-30
- Новый репозиторий и схема запуска: ZIP с заданием в `inbox/` → автоматический тест → отчёт в `reports/` и Telegram.
- Режимы: `audit`, `standard`, `final`, `targets`, `lab`, `plan`; параметры через файл-задание.
- Новое в диагностике: серверная диагностика (заголовки, время ответа), блок «Топ причин», этапы LCP, главный поток, сторонние скрипты, длинные задачи, неиспользуемый код, вес по типам, CrUX с корректным разбором, цветные пороги CWV.
- Параллельные потоки PSI (`parallel`), локальный Lighthouse (`lab`).
- Язык Lighthouse переключён на `en` (разбор этапов больше не зависит от русских формулировок).
- Сравнение с последним замером каждой страницы, а не только с предыдущим файлом.
- Очередь без потерь, защита от повторов, проверка путей в архиве.
- Основа — рабочий `site-check.mjs` (структурный аудит и PSI v1) и идеи из варианта другого специалиста (TTFB, главный поток, сторонние скрипты, пороги CWV).
