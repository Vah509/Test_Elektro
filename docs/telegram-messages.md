# Сообщения в Telegram (v2.3)

Принцип: одно событие — одно сообщение, акцент на проблемах, детали — в отчёте (ссылка на GitHub). Без вложений. Время — по Киеву.

| Событие | Сообщение |
|---|---|
| Скрипты обновлены | 🟢 скрипты обновлены и проверены · время |
| Ошибка обновления | 🔴 ошибка обновления скриптов / архив отклонён · время + причина, репозиторий не менялся |
| Расписание обновлено | 🗓 список записей (дата время — режим «имя») |
| Старт теста | 🟢 старт теста · время · имя (режим, сайт) [· по плану, задержка] |
| Тест выполнен | 🟢/🟡/🔴 тест выполнен · время · длительность + блоки Проблемы / Предупреждения + ссылка |
| Ошибка теста | 🔴 ошибка выполнения теста · время · длительность + причина + ссылка на запуск |
| Слот пропущен | 🟡 слот «имя» пропущен (опоздал больше graceHours) |
| «Расписание живо» | 💓 раз в сутки, если cron сработал, а запускать нечего. Тишина больше суток = cron не работает |

Цвет заголовка «тест выполнен» = худший результат. В блоке не больше 5 строк, остальное «+N ещё». Ссылка на отчёт заработает через ~1 минуту (отчёт коммитится в конце workflow).

## Пороги (как у Google)
| Метрика | 🟡 от | 🔴 от |
|---|---|---|
| PSI оценка | < 90 | < 50 |
| LCP | 2,5 с | 4 с |
| FCP | 1,8 с | 3 с |
| TBT | 200 мс | 600 мс |
| CLS | 0,1 | 0,25 |
| TTFB (сервер, медиана) | 800 мс | 1,8 с |

Значения — медианы прогонов. Разброс прогонов > 10 баллов → пометка ⚠ШУМ.

## Коды причин
Показываются только у страниц, у которых уже жёлтая или красная метрика (до 2 кодов на страницу).

| Код | Смысл | Условие |
|---|---|---|
| ЛЦП-ПЗ | LCP-картинка найдена поздно | доля этапа «load delay» ≥ 40% или discovery-оценка < 0,5 |
| ЛЦП-ВЕС | тяжёлый файл LCP | доля «load duration» ≥ 40% |
| ЛЦП-РНД | задержка отрисовки LCP | доля «render delay» ≥ 50% |
| ФОТО | LCP — картинка, этапы ничего не выделили | запасной код |
| БЛОК | блокирующие CSS/JS | экономия ≥ 300 мс при плохих FCP/LCP |
| СТОРОН | сторонние скрипты (GTM, Clarity) | ≥ 400 мс главного потока или ≥ 150 мс блокировки при плохом TBT |
| ЛИШ-JS | неиспользуемый JS/CSS | ≥ 150 КиБ |
| DOM | слишком много элементов | > 1500 |
| ТЯЖЕЛО | вес страницы | > 2000 КиБ |
| НЕТ-СЖ | нет br/gzip у HTML | 🔴 |
| КЭШ | cache-control у хешированных ассетов | 🔴 нет кэша; 🟡 меньше года |
| СРВ-ЛАГ | нестабильный или медленный ответ сервера | 🟡 медиана ≥ 800 мс или максимум ≥ 4× медианы; 🔴 медиана ≥ 1,8 с |
| ШУМ | разброс прогонов > 10 баллов | пометка, не проблема |

Замечания структурного аудита (ERR → 🔴, WARN → 🟡) идут в те же блоки по коду, сгруппированно.

## Что изменено в логике
- Ручной запуск с полем `job` больше не прерывает обработку: после него обрабатываются inbox и расписание.
- Добавлено «расписание живо» раз в сутки.
