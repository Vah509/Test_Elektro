# Обновление через ZIP и запуск по расписанию

## Обновление репозитория архивом
Кладёшь ZIP в `inbox/` (GitHub → Add file → Upload files) — дальше всё автоматически.
Разрешённые пути в архиве: `jobs/`, `targets/`, `scripts/`, `docs/`, `README.md` (без корневой папки). `.github/` через ZIP менять нельзя.

Что делает `process-jobs.mjs`:
1. Проверка путей и числа файлов (≤ 200).
2. Распаковка во временную папку, репозиторий пока не тронут.
3. Проверка: все `jobs/*.json` и `targets/*.json` — корректный JSON; `targets/schedule.json` — по правилам ниже; каждый `scripts/**/*.mjs` — `node --check`; пробный запуск `process-jobs.mjs` и `site-check.mjs help` в копии (текущие скрипты + новые поверх).
4. Всё прошло → файлы переносятся в репозиторий, в Telegram: «скрипты обновлены». Задания из архива запускаются.
5. Что-то не прошло → репозиторий не меняется, в Telegram: причина. ZIP удаляется в любом случае.

Ограничение: проверка ловит синтаксис и ошибки загрузки, но не логические ошибки. Новый скрипт стоит проверить коротким заданием (`mode: plan` или `audit`).

## Запуск по расписанию (необязательно)
Нужен один раз вручную вставить в `.github/workflows/site-check.yml` блок:
```yaml
on:
  schedule:
    - cron: '7,37 * * * *'
```
(готовый файл — `site-check.yml` рядом с этой инструкцией у Claude). Каждые 30 минут workflow смотрит `targets/schedule.json`; если ничего не пора запускать — завершается за ~20 секунд.

`targets/schedule.json`:
```json
{
  "tz": "Europe/Kyiv",
  "graceHours": 6,
  "entries": [
    { "name": "sat-morning", "at": "2026-10-31T10:00", "job": "jobs/sat-standard.json" },
    { "name": "weekday-check", "daily": "09:00", "days": [1,2,3,4,5],
      "from": "2026-11-02", "until": "2026-11-13", "job": "jobs/check.json" }
  ]
}
```
- `at` — разовый запуск, `daily` — каждый день (`days`: 1 = пн … 7 = вс; `from`/`until` — границы дат). Время локальное в `tz`.
- Файл задания, который нужен только расписанию, помечай `"scheduledOnly": true`: при загрузке в ZIP он сохранится, но сразу не запустится (без пометки любой `jobs/*.json` из архива запускается немедленно).
- Одно и то же задание можно использовать в нескольких записях: запуск по расписанию не блокируется «уже выполнялся».
- GitHub запускает cron с задержкой (бывает до часа). Если слот опоздал больше чем на `graceHours` — он пропускается с сообщением в Telegram.
- `"enabled": false` у записи — отключить, не удаляя.
- Выключить всё: удалить `targets/schedule.json` (или пустой `entries`).
- Сбой расписания: ошибка в файле → один раз сообщение в Telegram, остальная работа не страдает.
- GitHub отключает расписание в публичном репозитории после 60 дней без активности (коммиты отчётов считаются активностью).
